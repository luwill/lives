# 设计：把人生轨迹视频流水线打包成 skill，并做 A/B 评测

- 日期：2026-11-02
- 状态：设计已确认，待写实施计划
- 来源：`lives/` 项目的六部成片（毛泽东、诸葛亮、苏轼、李白、朱元璋、蒋介石），以及三份运行记录和三份经验笔记

## 目标

1. 把 `lives/` 的做法打包成一个可复用的 skill：给定一位中国历史人物，按同样的标准做出一部人生轨迹视频。
2. 用一次 A/B 评测回答：用 skill 做，和让 Opus 5.5 从零直接做，成片质量差多少。

## 范围

**在范围内**
- 按现状打包：引擎、工具、测试、配乐生成器、数据规范、流程与踩坑经验。
- 为了能加新人物而做的必要重构（下文“去人物化”）。
- A/B 评测，人物为粟裕。

**不在范围内**（用户决定暂不做）
- 配乐、配音、图像素材的升级。
- 引擎全球化。skill 说明中写明：**仅限主要活动在中国的历史人物**。

## 1. skill 结构

名称 `life-trajectory-video`，安装在 `~/.claude/skills/`，形态为“自带完整模板”。以后以 skill 为代码的权威来源，`lives/` 保留为历史项目。

```
life-trajectory-video/
├── SKILL.md              流程总纲：适用范围、开工问清单、各阶段检查点
├── references/
│   ├── schema.md          数据规范（来自 data/SCHEMA.md，加入 person.json）
│   ├── research-brief.md  史料研究代理任务书模板（含前两批核查教训）
│   ├── factcheck-brief.md 独立核查代理任务书模板
│   ├── narration.md       旁白写法与详略标准
│   └── pitfalls.md        踩坑清单（规则 + 原因，取自经验笔记与运行记录）
├── template/              项目模板：src/、tools/、music/、tests/、render.mjs、package.json
└── scripts/
    ├── new_project.sh     从模板生成工作目录、检查环境依赖
    └── setup_terrain.sh   准备共享地形缓存
```

### 1.1 去人物化

现在加一个新人物要在 6 处改代码：`people.js`（年号表、年龄算法、政权注记、地形层）、`tts.py` 的声线表、`assemble.sh` 的中文名表、`tests/conftest.py` 的人物名单、`tools/smoke.mjs` 的人物名单，以及测试里写死的生卒区间和里程碑下限。

改为每个人物一份配置 `data/<who>/person.json`，代码只读配置：

| 字段 | 内容 |
|---|---|
| `name`、`life`、`tagline`、`color`、`glow` | 显示信息与配色 |
| `age` | `{"kind": "xusui", "lunar_birth_year": 701}` 或 `{"kind": "zhousui", "birth": "1887-10-31"}` |
| `birth_override` | 可选：出生一步的纪年和年龄显示（苏轼生于农历年末的情形） |
| `eras` | 年号表，每行 `[前缀, 年号, 元年, 生效半年 "YYYYH1/H2"]` |
| `era_overrides` | 可选：按半年区间覆盖纪年文字的规则（天宝称“载”、龙凤与至正并列、1949H2 起不显示等） |
| `regions` | 时代政权注记：名称、坐标、起止半年 |
| `voice` | TTS 声线、语速、音调 |
| `levels` | 可选：额外的高清地形层（默认使用共享层） |
| `targets` | 时长区间、里程碑数量下限（测试读取） |

现有六人的配置迁移到 JSON。已有的年龄、纪年锚点测试是迁移的回归保护：迁移前后，六人每个半年步的年龄和纪年文字必须逐字一致（迁移前先导出一份基线快照，用测试对比）。

### 1.2 环境依赖

- Chromium 路径不再写死为 `chromium-1243`：先读环境变量 `LTV_CHROME`，没有就在 Playwright 缓存目录里自动查找。
- `new_project.sh` 一次列出所有缺失项（ffmpeg、node、three、playwright-core、numpy、scipy、Pillow、edge-tts），询问后再安装。
- `lunar_python` 列为可选依赖：只在农历换算时用；没有它，流程可以照常进行，只是研究代理要改用查表。

### 1.3 地形缓存

- 位置：`~/.cache/life-trajectory-video/terrain/`。
- 首次运行时，如果本机有 `lives/assets/terrain`，就复制已有的层（world、china、east、zhuge_hi、hi_north、hi_east、hi_south、hi_japan）；否则下载生成，约 30–60 分钟。
- 人物有地点落在高清层之外、但又在底图范围内时，按这些地点的范围自动补一块高清层，写进 `person.json` 的 `levels`。
- 每个工作目录用符号链接指向缓存，不复制。

## 2. SKILL.md 中的流程

| 阶段 | 做什么 | 怎样算通过 |
|---|---|---|
| 0 开工问清单 | 一次性问齐：适用范围（半年步中有超过 20% 停留在地图范围 72–146°E、16–54°N 之外，就说明不适用并停下；10%–20% 之间提醒用户，由用户决定）；措辞立场；年龄口径（默认古人虚岁、近人周岁）；纪年显示规则；声线（可试听样音）；目标时长；引文繁简（默认简体）；是否授权删除逐帧中间产物；地图审图提醒 | 回答写进 `person.json` 和运行记录 |
| 1 建目录 | `new_project.sh`、环境检查、地形缓存 | 环境检查全过，页面能加载 |
| 2 史料研究 | 研究代理按任务书产出 `steps.json`、`places.json`、`person.json` | 代理自测 `pytest -k <who>` 通过后交付 |
| 3 独立核查 | 另派代理逐个里程碑核对（每个 ≥2 个来源），产出 `factcheck-<who>.md`；每条修正在数据、旁白、卡片三处同步 | 无“错误”级问题；存疑项进 `contested`，旁白用审慎措辞 |
| 4 旁白与时间轴 | 写旁白 → TTS → `build_timeline` | 详略比例、字幕不重叠、配音与文本哈希一致等测试通过 |
| 5 配乐 | 阶段—情绪映射 `<who>_stages.json`，生成配乐，出音频指标报告 | 阶段边界无静音，响度在范围内 |
| 6 定点审片 | 每个里程碑、章节卡、片头、片尾各出一张静帧，拼成拼板，按缺陷清单逐张审 | 清单逐项通过；有问题先修再进入下一阶段 |
| 7 全片渲染 | `render_all.sh`，`check_outputs --require` | 规格、响度、时长、无黑帧 |
| 8 交付 | 运行记录（做了什么、未验证清单、给人看的验收时间点），经验笔记 | — |

人工检查点只在阶段 0 和阶段 8。例外：阶段 3 出现立场措辞问题，或某个里程碑存在重大事实争议时，暂停请人定夺。

每条规则后附一句原因，原因取自真实踩过的坑。例如：图外判定以底图实际覆盖范围为准，因为东京曾被投到日本海上。这样模型遇到没见过的情况，也能按原则推断。

### 2.1 定点审片缺陷清单（阶段 6）

- 地点标记是否落在正确的陆地或水域上（与卫星底图对照）
- 地名注记是否互相压叠，是否压住 HUD、卡片或字幕
- 里程碑卡片是否遮住当前地点
- 轨迹线是否出现无端点的异常长线，远途镜头是否把整段路线框进画面
- 左上角的年份、纪年、年龄是否与卡片一致
- 章节卡、片头、片尾文字是否完整、无溢出
- 片尾回放的光带是否出现

## 3. A/B 评测

### 3.1 输入

- 两组的需求原文相同：
  > 给粟裕做一部人生轨迹视频：半年一步、结合史料；在中国 3D 地形上展开并标注地名；里程碑高亮；按人生阶段配不同 BGM；讲解详略得当。
- 两组拿到同一份“决策单”：评测开始前，由用户回答阶段 0 的问题（措辞立场、年龄口径、声线、目标时长等），整理成文件分发给两组。

### 3.2 隔离

- 两组都由全新的子代理执行，模型均为 Opus 5.5；主会话不参与制作。
- 目录：`ab/bare/`、`ab/skill/`，位于已受信任的父目录下，并从父目录派发。
- 从零组的任务书禁止读取 `lives/`、`learnings/`、skill 目录和历史会话记录。主会话会检查它的工具调用记录，越界则作废重跑。
- 自动记忆索引会注入所有会话，无法屏蔽。其内容是环境配置类笔记，与视频方法无关，在报告中注明。
- 两组都自主跑到宣布完成为止，中途不给人工反馈，上限 4 小时；超时记为“未完成”。

### 3.3 评价

| 维度 | 方法 |
|---|---|
| 能否交付 | 是否产出合格 mp4：1080p，有旁白和配乐，时长合理 |
| 史实 | 第三个代理用同一份核查任务书检查两组里程碑；产出匿名为甲、乙；统计每个里程碑的错误数和存疑数 |
| 画面 | 两组都按每 30 s 一帧，加每个里程碑一帧，出静帧，用 2.1 的清单统计缺陷数 |
| 成本 | 总耗时、工具调用次数、token 用量（取自子代理结果统计） |
| 主观 | 用户观看两部成片并打分，作为最终裁判 |

### 3.4 局限

只有一个人物、每组只跑一次，结果只能作为方向性参考，报告中写明。如果差距不明显或有争议，可以再加一个古代人物重跑。

产出：`lives/docs/evidence/ab-suyu.md`（对比报告），两部成片分别放在 `ab/bare/`、`ab/skill/`。

## 4. 测试与验收

- skill 模板自带的测试：数据规范、时间轴、年龄纪年（含六人基线快照比对）、JS 纯函数、smoke。
- skill 打包完成的标准：用模板重建六人中的一人（建议苏轼），时间轴与现有成片一致，`smoke` 和 `check_outputs` 通过。
- 评测完成的标准：两组都已运行完毕（或超时），对比报告各项有数据，用户已给出主观打分。

## 5. 风险

| 风险 | 对策 |
|---|---|
| 去人物化迁移改变了现有人物的纪年或年龄显示 | 先导出基线快照，逐字比对 |
| 从零组越界读取已有成果 | 任务书禁止 + 检查工具调用记录，越界作废 |
| 子代理卡在信任提示上 | 从已受信任的父目录派发 |
| 渲染占用磁盘（单部约 10–16 GB 逐帧） | 阶段 0 询问是否授权删除中间帧；评测前检查剩余空间 |
| 粟裕题材的措辞敏感 | 决策单中明确立场；核查阶段专门检查措辞 |

## 实现差异

- 额外分层字段实际名为 `extra_levels`（`person.json` 中 `[层名, 数值]` 列表），而非设计稿中的写法。
- 模板不带基线夹具（`tests/fixtures/era_baseline.json`），因此模板中对应的基线比对测试会跳过；lives 仓库保留该夹具并启用。
- 高分辨率地形层不是自动检测并生成：由 SKILL.md 指引检测需要后手动生成，没有自动化步骤。
